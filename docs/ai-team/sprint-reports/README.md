# Sprint reports

**Who:** Scrum Master writes these. Anyone on the team may read them.

**What this is:** A dated, human-readable copy of overnight Scrumban so Jacob (and a junior SM) can learn the stream. It is **not** the live record. The live record is # heliopoly build.

**What this is not:** A fifth ceremony. Not a weekly VSM workshop. Not a place to prioritize (Product Owner). Not production code.

## When a file gets written

After 2:00 sprint review and 2:30 retro (America/Chicago). One file per calendar day: `YYYY-MM-DD.md`. If overnight produced nothing true, write that in one line. Do not invent board or git data.

## How to read a day (junior SM)

1. **Goal vs live** — did heliopoly.live move? Preview is not Done.
2. **Wait line** — where work sat (days on preview without In review, days in unmerged phone PRs).
3. **Mermaid map** — same boxes every day unless the *path* changed (new host, second Done for phone). Inventory is the pile sitting in a box. Wait is how long it sat.
4. **Retro** — 0–2 working-agreement changes. Zero is allowed.
5. **HITL** — which surface: `preview.heliopoly.live` or physical iPhone. Never mix on one ticket. Never localhost.

## Folder rules

- Plain English first. Ticket numbers in parentheses after the English name.
- Copy the template. Do not add new sections without a retro.
- Room conversation stays in the room. This file is the durable sketch.
